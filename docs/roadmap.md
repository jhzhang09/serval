# 开发计划

目标：功能对齐 Netcatty 的核心用法，在轻量、好看、易用、数据可同步上做得更好。本文按里程碑排列任务，每个任务写明范围、涉及文件、验收标准和依赖，可以单独交给一个 agent 完成。

领任务前先读 [AGENTS.md](../AGENTS.md) 和 [architecture.md](architecture.md)。

## 怎么用这份计划

- **任务编号**：字母表示领域（F 基础、C 连接、T 终端、S 同步、P 文件、N 网络、R 发布、M 移动端），数字表示顺序。分支名用编号，例如 `feat/S1-webdav`。
- **规模**：S（半天以内）、M（一到两天）、L（三天以上，建议先拆分或先交设计稿）。
- **依赖**：列出的任务完成并合并后才能开始。
- **需决策**：标了“需决策”的事项，由项目所有者拍板后才能实现；agent 可以先提交备选方案，但不要自己定。
- **完成**：满足“验收标准”的每一条，并通过 [review-checklist](review-checklist.md)。完成后在本文把状态改成“已完成”，写上分支名。
- **范围外的发现**：做任务时发现的其他问题，记到本文末尾“待整理”，不要顺手修。
- **状态标记**：“已完成”表示验收通过并已合并到 main；“修改中”“返工”表示验收未通过，修改要求见对应的验收报告（[docs/reviews](reviews)），在原分支上继续提交。

## F 基础

### F1 正式的应用标识符（S，已完成：`feat/F1-app-identifier`）

- **背景**：确定正式的应用标识符为 `io.github.jhzhang09.serval`，和仓库 `github.com/jhzhang09/serval` 对应。系统安全存储（macOS 钥匙串、Windows 凭据管理器、Linux Secret Service）按它区分应用，隔离本应用的数据。
- **变更记录**：2026-11-08 由 `io.github.serval-app.serval` 改为现值（仓库建在个人账号下，没有 `serval-app` 组织）。保险库在配置目录 `Serval` 下，不受影响；旧标识符下“在这台设备上记住”的钥匙找不到了，第一次启动新版本要输入一次主密码，勾选“记住”后写入新条目。以后不要再改：每改一次，所有用户都要重新输入主密码。
- **范围**：改 `mygo.json`；README 的打包说明。
- **验收**：打包后 `codesign -dv` 显示新标识符；“记住”失效后能用主密码解锁，并重新记住。

### F2 设置存储（M，已完成：`feat/F2-settings`）

- **背景**：外观（浅色/深色）现在只在内存里，重启就丢；终端设置（T1）、同步设置（S2）都需要地方存。
- **范围**：
  - 区分两类设置：**随同步**的（外观、终端字体与主题、代码片段默认值）存进保险库，记录类型 `settings`，固定 ID；**只属于本机**的（窗口位置已由 MyGo 管理、同步账号的本机令牌、最近使用）存配置目录下的 `device.json`，不进保险库。
  - `library.go` 增加读写接口；设置面板入口放在命令面板和侧栏。
- **涉及**：新文件 `settings.go`；`app.go`（`appearance` 字段改为读设置）；`palette.go`。
- **验收**：切换外观后重启仍然生效；两份保险库 `Merge` 后设置按版本号取较新者（单元测试）；本机设置不出现在 `vault.json` 里。
- **依赖**：无。

### F3 修改主密码、手动锁定、自动锁定（M，已完成：feat/F3-password-lock）

- **背景**：`vault.ChangePassword` 已实现，但没有界面；也没有锁定入口。
- **范围**：
  - 设置面板里“修改主密码”：当前主密码、新主密码、再输一次。保险库密钥 VK 不变，所以本机记住的钥匙和其他设备都不受影响（其他设备同步后改用新主密码）。
  - 命令面板“锁定”：关闭全部会话前先确认（列出将关闭的会话数），然后 `vault.Lock()` 并显示锁定页面。
  - 自动锁定：设置里可选“闲置 N 分钟后锁定”（默认关闭），属于本机设置（F2）。
  - 关闭“在这台设备上记住”的开关。
- **涉及**：`library.go`、`sheets.go`、`palette.go`、`settings.go`。
- **验收**：改主密码后旧主密码解锁失败、新主密码成功（界面测试）；锁定后主机列表不可见、内存里 `a.hosts`/`a.keys` 为空；自动锁定在设定时间后生效（测试里用可注入的时钟）。
- **依赖**：F2。

### F4 主密码派生移出主线程（S，已完成：`feat/F4-async-kdf`）

- **背景**：Argon2id（64 MiB，约 0.1 秒）在主线程执行，设置主密码和解锁时界面会停顿。
- **范围**：`submitSetup`、`submitUnlock` 改为后台执行，期间按钮显示“正在解锁…”并禁用，结果用 `a.post` 回来；重复点击不触发第二次。
- **涉及**：`library.go`、`sheets.go`。
- **验收**：界面测试覆盖“处理中按钮禁用”和“完成后状态正确”；`go test -race` 通过。
- **依赖**：无。

### F5 已知主机管理（S，已完成：`feat/F5-known-hosts`）

- **背景**：信任记录只能在主机菜单里“重置主机密钥”，看不到全部记录，也删不掉已经不存在的主机的记录。
- **范围**：设置或密钥面板里新增“已知主机”列表：地址、密钥类型、指纹、添加时间；可删除单条。
- **涉及**：`knownhosts.go`、新面板。
- **验收**：列表与保险库内容一致；删除后下次连接重新核对指纹（界面测试）。
- **依赖**：无（如 F2 已完成，可放进设置面板）。

### F6 主机改名时更新跳板机引用（S，已完成：`feat/F6-rename-jumps`）

- **背景**：其他主机的 `ProxyJump` 按名称引用跳板机，改名后引用失效。
- **范围**：保存改名时，在同一次 `apply` 里把其他主机 `ProxyJump` 中的旧名称替换为新名称；表单里提示“将同时更新 N 台主机的跳板机设置”。
- **验收**：改名后经它跳转的主机仍能解析链路（单元测试 + 界面测试）。
- **依赖**：无。

### F7 主机搜索与排序（S，已完成：`feat/F7-host-search`）

- **范围**：侧栏搜索框直接过滤（现在点击打开命令面板）；分组可折叠，折叠状态是本机设置。
- **实现**：过滤框匹配名称、用户、地址和分组，不区分大小写；没有匹配时提示。分组标题可折叠，状态写入 `device.json` 的 `collapsedGroups`，不进保险库；正在过滤时暂时展开，避免把结果藏起来。同一分组内按名称排序（不区分大小写，同名保持原顺序）。命令面板改由过滤框右侧的快捷键按钮和 ⌘K 打开。
- **依赖**：F2。

### F8 主机手动拖动排序（S，已完成：`feat/F8-host-drag-order`）

- **范围**：侧栏主机支持鼠标拖拽自由调整在分组内的排序，以及直接拖入其他分组；排序权重写入保险库（随设备同步），未手动调整的主机保持默认按字母排序。
- **实现**：`hosts.Host` 新增 `SortOrder int`（`json:"sortOrder,omitempty"`），登记进 `docs/storage.md`。使用 MyGo 的 `Drag`、`DragOver` 与 `Drop` 实现窗口内拖拽与边框高亮反馈；拖到同组目标行调整前后顺序，拖到其他分组行或折叠标题行跨组归类并更新排序权重，写入保险库。
- **依赖**：F7。

## C 连接

### C1 快速连接（S，已完成：`feat/C1-quick-connect`）

- **范围**：命令面板输入 `user@host[:port]` 时出现“连接 user@host”选项，直接连接临时主机（不保存）；连接成功后，标签上提供“保存为主机”。
- **涉及**：`palette.go`、`app.go`（临时主机不在保险库里，`rememberCredentials` 已跳过非保存主机）。
- **验收**：界面测试覆盖临时连接、保存为主机后出现在侧栏；临时主机的密码不被保存。
- **依赖**：无。

### C2 多步验证（keyboard-interactive）（M，已完成：`feat/C2-keyboard-interactive`）

- **背景**：现在只回答单个隐藏输入的提示；服务器要求多步验证（OTP、多个问题）时直接报错。
- **范围**：
  - `core/sshconn`：`Config` 增加回调 `Challenge func(name, instruction string, questions []Question) ([]string, error)`，在连接 goroutine 里调用。
  - 应用层：通过 `a.post` 弹出面板，逐题显示（回显与否按服务器要求），用 channel 等待回答，取消时返回错误。
  - devsshd 增加 keyboard-interactive 模式用于测试。
- **验收**：sshconn 单元测试覆盖多问题、取消、超时；界面测试覆盖回答 OTP 后连接成功。
- **依赖**：无。

### C3 TOTP 自动填充（M，已完成：`feat/C3-totp`）

- **范围**：主机记录增加 TOTP 密钥（属于秘密，`requireProtection`）；多步验证遇到验证码问题时自动填写；主机表单里可粘贴 `otpauth://` 链接。实现 RFC 6238（标准库 `crypto/hmac` 即可）。
- **验收**：RFC 6238 测试向量通过；界面测试覆盖自动填写。
- **实现**：`core/totp` 支持 SHA1、SHA256、SHA512，以及 6/8 位和自定义周期。问题文本不像验证码时仍交给用户。不支持 HOTP。
- **依赖**：C2。

### C4 自动重连与会话恢复（M，已完成：`feat/C4-auto-reconnect`）

- **范围**：
  - 网络中断（保活失败）时自动重连，指数退避（1、2、4…最多 30 秒），窗格显示“正在重连（第 N 次）”，可取消；重连成功后在原窗格打开新 shell。
  - 启动时恢复上次打开的标签和窗格布局（本机设置，不同步），可在设置里关闭。
- **涉及**：`app.go`（`watchLatency`、窗格树）、`settings.go`。
- **验收**：测试里关闭再启动 devsshd（同一端口、同一主机密钥：给 devsshd 增加固定主机密钥选项），会话自动恢复；恢复布局的界面测试。
- **依赖**：F2。

### C5 本地终端（S，已完成：`feat/C5-local-terminal`）

- **背景**：MyGo 终端插件自带在伪终端里运行本机 shell 的能力（`terminal.New(terminal.Options{})`）。
- **范围**：侧栏和命令面板“本地终端”；本地标签没有文件抽屉的 SFTP（以后可以接本地文件）；窗格拆分照常。
- **验收**：macOS 上打开本地终端运行命令（界面测试）；Windows、Linux 上手动验证（随 R1、R2）。
- **依赖**：无。

### C6 ssh-agent 转发（S，已完成：`feat/C6-agent-forward`）

- **范围**：主机选项“转发 ssh-agent”（默认关闭，开启时提示安全风险）；`core/sshconn` 用 `agent.ForwardToRemote`。
- **验收**：经跳板机连接后，在目标主机上 `ssh-add -l` 能看到本机 agent 的钥匙（集成测试）。
- **实现**：选项写在主机记录 `forwardAgent`。连接目标时转发；本机没有 agent 则整次连接失败并说明原因。开发服务器会去掉继承来的 `SSH_AUTH_SOCK`，避免测试误把本机套接字当成转发成功。

### C7 证书与硬件密钥（L，需决策）

- **范围**：OpenSSH 证书认证；FIDO 硬件密钥（`sk-ed25519`）。硬件密钥需要平台原生接口，工作量大。
- **需决策**：是否做、优先级。

## T 终端

### T1 终端设置（M，已完成：feat/T1-terminal-settings）

- **范围**：字体（优先已安装的等宽字体）、字号、行高、光标样式、回滚行数、配色主题（MyGo 终端插件自带 Ghostty 的主题列表，浅色和深色各选一套）。设置随同步。可选：单台主机覆盖主题（生产环境默认用偏红的主题，需决策）。
- **涉及**：`design/tokens.go`（`Terminal`、`TerminalFont` 改为读设置）、`settings.go`、设置面板。
- **验收**：修改后已打开的终端立即生效；重启保留；对比度测试仍然通过（`design/tokens_test.go`）。
- **依赖**：F2。

### T2 终端内搜索（S，已完成：`feat/T2-terminal-search`）

- **背景**：终端插件自带搜索（见 MyGo 文档 plugins/terminal.md 的 Search 一节）。
- **范围**：⌘F 打开搜索条，上一个/下一个。（原计划的“区分大小写”开关不做：MyGo 终端插件的搜索固定对 ASCII 字母不区分大小写，没有提供选项。验收时确认。）
- **验收**：界面测试覆盖搜索命中与跳转。

### T3 广播输入（M，已完成：`feat/T3-broadcast`）

- **范围**：把键盘输入同时发送到选中的多个窗格（批量操作多台服务器）；开启时窗格边框明显标记，避免误操作；生产环境的窗格加入广播时二次确认。
- **已知限制**：本机终端作为输入源时只转发字母、数字、空格和常用控制键（回车、Tab、退格、方向键、Ctrl+字母等），标点、符号和输入法上屏的整段文字不广播——这些按键的字节编码跟随终端和输入法设置，猜错会发出错误字节，宁可少发。远程窗格作为输入源时按收到的原始字节转发，不受此限制。
- **验收**：界面测试覆盖输入同时到达多个窗格；生产环境确认。

### T4 会话日志（M，已完成：`feat/T4-session-log`）

- **范围**：可选把终端输出记录到用户选择的目录（纯文本，去掉控制序列）；默认关闭；日志文件不进保险库。
- **验收**：日志内容与终端显示一致（单元测试去除控制序列）。
- **实现**：开关和目录写在本机 `device.json`。只记录远程窗格；去掉颜色和控制序列，回车、退格作用在当前行。光标定位和清屏不模拟，全屏程序的日志不是屏幕回放。本地终端的输出由插件直接读取，不记录。日志文件权限 0600。

### T5 关键词高亮（M，不做，方案：`docs/proposals/T5-highlight.md`）

- **范围**：按规则高亮终端输出（如 `ERROR` 红色、`WARN` 黄色）；规则随同步。需要先确认终端插件是否支持按内容着色，不支持时提交方案再做。
- **结论**：已确认不做。MyGo v0.8.1 终端插件不支持非破坏性叠加着色；自绘浮层或写入 ANSI 都会破坏复制与全屏程序，实时正则匹配也会影响高吞吐性能并容易误染已有配色，且终端内搜索（`⌘F`）已能满足定位需求。

### T6 代码片段（M，已完成：`feat/T6-snippets`）

- **范围**：保险库新记录类型 `snippet`（名称、内容、可选变量）；命令面板搜索并发送到当前窗格；多行内容发送前确认。

## S 同步

### S1 WebDAV 同步（L，已完成：`feat/S1-webdav`）

- **范围**：
  - 同步引擎（`sync.go`，应用层或新的 `core/syncer`）：下载远端 `vault.json` → `vault.Merge` → 上传合并结果。上传用 `If-Match`（ETag）防止覆盖别人刚上传的版本，冲突时重新下载合并再上传，最多重试 3 次。
  - WebDAV 客户端只需要 GET、PUT、PROPFIND/HEAD（标准库 `net/http` 实现，不加依赖）。
  - 触发时机：启动解锁后、每次本地写入后（去抖 3 秒）、每 5 分钟、手动“立即同步”。
  - 同步账号密码属于秘密：存进保险库还是本机设置需要权衡（存保险库则新设备要先拿到保险库才能拿到账号，形成鸡生蛋）。建议：WebDAV 地址和账号存本机设置，密码存系统安全存储。
- **验收**：用本地 WebDAV 测试服务器（可用 `golang.org/x/net/webdav` 在测试里起一个）验证：两台“设备”各自修改后同步，结果一致；并发上传时 ETag 冲突能重试成功；断网时不丢本地修改，恢复后补同步。
- **实现**：引擎在 `core/syncer`（标准库 HTTP，无新依赖）。地址和账号在 `device.json`，密码在系统安全存储。解锁后、本地写入去抖 3 秒、每 5 分钟，以及命令面板“立即同步”都会触发。设置面板是 S2。`golang.org/x/net/webdav` 会发 ETag 但不检查 `If-Match`，测试里在它外面补了这一层。
- **依赖**：F2。

### S2 同步设置与状态（M，已完成：`feat/S2-sync-settings`）

- **范围**：设置面板“同步”：服务地址、账号、测试连接、启用/停用、上次同步时间、错误信息；侧栏底部显示同步状态（不打扰的小图标）。
- **实现**：设置页第三段。保存走 `configureSync`：地址和账号进 `device.json`，密码只进系统安全存储，留空表示不改已存密码。测试连接只做一次 GET，文件还不存在也算连上。侧栏在开启同步或正在同步、同步失败时显示状态，点击打开同步页。自动失败仍不弹 toast。
- **依赖**：S1。

### S3 新设备加入（M，已完成：`feat/S3-restore`）

- **范围**：首次启动（本地没有保险库或保险库为空）时提供“从同步恢复”：填写同步服务 → 下载 → 输入主密码解锁 → 完成。本地已有数据时提示合并而不是覆盖。
- **实现**：空保险库有自己的 VaultID，不能 `Merge`。`Vault.Adopt` 只在本地没有任何记录时整份换上远端文件。侧栏空状态的“从同步恢复”下载后进入锁定页，用原来的主密码解锁。已有数据的设备第一次开启同步时弹出“与已有数据合并？”，默认取消；确认后仍走按记录合并。
- **验收**：界面测试覆盖空设备加入；已有数据的设备加入后两边数据合并。
- **依赖**：S1。

### S4 S3 兼容存储（M，已完成：`feat/S4-s3-sync`）

- **范围**：AWS S3、Cloudflare R2、MinIO 等。用条件写入（`If-Match`）防覆盖。纯 Go 标准库实现 AWS SigV4 认证签名，不引入外部重型 SDK。
- **实现**：`core/syncer/s3.go` 支持标准 AWS SigV4 计算与路径模式（Path-Style）；设置与恢复面板支持直接输入 `s3://bucket/vault.json`（支持带 `endpoint` 和 `region` 参数），凭据（AccessKey/SecretKey）存入系统安全存储；两端并发修改时经由 ETag 乐观锁触发重新拉取并由混合逻辑时钟在本地完成合并后再上传，集成测试覆盖两设备收敛与空设备恢复。
- **依赖**：S1。

### S5 同步文件夹（S，已完成：`feat/S5-sync-folder`）

- **范围**：把保险库副本放进用户选择的文件夹（iCloud Drive、Dropbox、Syncthing），监听文件变化后合并。只适合桌面；要处理同步软件生成的“冲突副本”文件（逐个合并后删除，删除前确认）。
- **实现**：设置页选择文件夹，路径记在 `device.json` 的 `syncDir`。本地修改后立刻把加密的 `vault.json` 写进该文件夹；每 5 秒读回，有变化就 `Merge`。识别 Syncthing 的 `.sync-conflict-` 和 Dropbox / Nextcloud 的 `conflicted copy`。删除前用确认框，默认取消；取消后同一份文件不再反复问，文件变化后才再问。不用新依赖，轮询而不是文件系统监听。文件夹里若是另一个保险库，不覆盖。
- **依赖**：S1。

- **依赖**：P1（共用 `files.go`）。

### P3 拖放（M，已完成：`feat/P3-drawer-transfer`）

- **范围**：从 Finder/资源管理器拖进文件抽屉上传；从抽屉拖到桌面下载（MyGo 的拖放 API）；抽屉里选择文件夹上传、下载文件夹。
- **拖到终端（已在 main）**：用 SFTP 传到终端当前目录（shell 用 OSC 7 上报的目录，没有上报时传到主目录并提示）；同名文件逐个确认。文件夹：远端已有同名文件夹时合并进去，有同名文件时只问一次（全部替换 / 全部跳过 / 取消）；符号链接和特殊文件跳过并提示；远端同一位置类型不同（文件对文件夹）时说明原因并停止；传输队列里显示成一行，按文件数和字节汇总进度；取消时保留已传完的文件。终端控件自己接收拖放且在最里层，所以只在有文件悬停时铺一层接收层（`view.go` 的 `dropLayer`），平时不影响终端的鼠标操作。本地终端保持默认行为：粘贴路径。
- **抽屉（本分支）**：拖进抽屉上传到抽屉当前列出的目录，不是终端工作目录。工具栏“上传文件夹”选择本地文件夹，规则与拖文件夹相同。目录行菜单“下载文件夹”递归下载，不跟随符号链接；本地已有同名文件或文件夹时不覆盖。取消时保留已下完的文件。
- **拖到桌面**：MyGo v0.8.1 的 `transfer.FileData` 只接受已经存在的本地路径，不支持文件承诺（松手时再生成文件），提供数据的函数也不能在主线程上等待下载。因此第一次拖动开始把文件下到临时目录并提示，下载完成后再拖一次才交给访达或资源管理器。只声明复制，避免对方把临时文件移走。窗口关闭时删除临时目录。
- **依赖**：P1。

### P4 内置编辑器（L，已完成：`feat/P4-editor`）

- **评估**：MyGo v0.8.1 的 `ui.TextBuffer` 加 `TextAreaBuffer` 可以编辑纯文本，字符串绑定每次都会复制全文，所以用文本缓冲。`ui/richtext` 是富文本，不适合当代码编辑器。文本框没有按规则着色的接口，语法高亮后做，本分支不另画一层文字、也不往文件里插颜色码。
- **范围**：文件抽屉里对普通文件右键“编辑”。保存写回该路径；打开时记下大小和修改时间（精确到秒），保存前再看一次，不一致就问“仍然保存”或“取消”（取消是默认按钮）。超过 1 MB 不读正文。含 NUL、不是合法 UTF-8、符号链接、目录和其他特殊文件都拒绝。macOS 用 ⌘S 保存，其他平台用 Ctrl+Shift+S，和现有应用快捷键同一套修饰键。锁定保险库时丢掉未保存的编辑。
- **不做**：语法高亮、换行符转换、保留原来的权限位（写回走现有上传，先写临时文件再改名）。同一秒内大小也没变的替换发现不了。
- **验收**：`TestReadLimitedRejectsBinaryHugeAndSymlink`、`TestWriteFileDetectsRemoteChange`、`TestEditorSavesConflictAndDiscard`、`TestEditorRejectsBinaryAndHuge`。
- **依赖**：P1。

### P6 终端里的 rz/sz（ZMODEM）（M，已完成：`feat/P6-zmodem`）

- **背景**：在终端里直接 `rz` 上传、`sz` 下载是很多人的习惯，不用另开文件窗口。lrzsz 和 Netcatty 都是 GPL，`core/zmodem` 按 Forsberg 的协议文档自己实现。
- **范围**：识别终端输出里的 ZMODEM 起始信号；`rz` 时弹出可多选的文件选择框，`sz` 时在第一个文件到达时问保存文件夹（同一次传输只问一次）；窗格里显示进度，可以取消（按钮或 Ctrl+C）；收到的文件先写临时文件，完成后才改名，同名不覆盖、自动编号。
- **安全**：对端给的文件名只取最后一段并去掉控制字符；ZCOMMAND（远程执行命令）一律拒绝。lrzsz 的等待时间有限（实测 rz 约 50 秒、sz 发出文件信息后 60 秒），用户考虑太久时直接放弃、不再向连接写任何东西，避免数据被 shell 当成命令执行。
- **不支持**：断点续传、压缩、tmux 里的 rz/sz（tmux 会改写数据流）、上传文件夹。
- **验收**：`core/zmodem` 与真实 lrzsz 互通测试（需要本机安装 lrzsz，没有时跳过）；端到端测试在开发用 SSH 服务器上运行真实的 rz/sz。

### P5 双栏文件浏览（M，已完成：`feat/P5-dual-pane`）

- **范围**：文件抽屉并排两栏。左侧是本机目录（默认主目录，测试里换成临时目录），右侧仍是当前会话的远程目录。把文件或文件夹从一侧拖到另一侧就传输：传到远端沿用上传的替换确认和文件夹合并；下到本机时本地已有同名文件或文件夹则不覆盖。拖到文件夹行上时，放进那个文件夹。同一栏里松开不传输。
- **和拖到桌面的关系**：窗口内拖动用 MyGo 的 `Drag`/`Drop`。远程文件要拖出窗口时，松手在窗口外才开始下载临时副本，副本好了之后下一次拖动才交给访达（和 P3 一样，因为 `FileData` 不能承诺尚未存在的文件）。已经能拖出的文件，这次手势走系统拖放，不再交给另一栏。
- **验收**：`TestDualPaneDragsBothWays`；拖到桌面仍由 `TestDragOutOffersFileAfterDownload` 覆盖。
- **依赖**：P3。
