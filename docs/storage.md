# 数据存储与同步设计

状态：已确认（2026-11-07）。本机保险库和私钥管理已实现，同步待实现。

## 目标

1. 主机、私钥、密码等全部用户数据存在 Serval 自己的**加密保险库**里，不依赖任何平台的钥匙串，这样 macOS、Windows、Linux 上的数据完全一样，可以同步。
2. 同步服务只能看到密文，看不到主机名、用户名，更看不到密码和私钥（零知识）。
3. 现在先做本机存储，但格式一开始就按同步来设计，以后加同步不用迁移数据。

## 参考：Netcatty 怎么做

| 方面 | Netcatty | Serval 的取舍 |
|---|---|---|
| 本机保护 | Electron `safeStorage`（底层是系统钥匙串）加密单个字段 | 不用系统钥匙串，改用主密码派生的密钥，各平台一致 |
| 同步加密 | 主密码 → PBKDF2（60 万次）→ AES-256-GCM，整个数据包加密 | 主密码 → Argon2id → 包裹随机的保险库密钥；按记录加密 |
| 同步服务 | GitHub Gist、Google Drive、OneDrive、S3、WebDAV | 先做“同步文件夹”和 WebDAV，其余以后按需加 |
| 冲突处理 | 有一套“收敛同步”逻辑 | 按记录的“后写入者胜”，删除用墓碑记录 |

## 密钥层级

```
主密码 ──Argon2id(盐, t=3, m=64MiB, p=4)──▶ 包裹密钥 KEK（只在内存里）
                                              │ 解开
保险库头里的 wrappedVaultKey ──────────────────┘
                                              ▼
                              保险库密钥 VK（32 字节随机数，只在内存里）
                                              │ XChaCha20-Poly1305
                                              ▼
                                    每条记录的密文
```

- **VK 是随机生成的**，主密码只用来包裹它。改主密码只需要重新包裹 VK，不用重新加密所有记录；以后同步时，其他设备输入同一个主密码就能解开同一个 VK。
- **Argon2id** 抗 GPU 暴力破解，比 PBKDF2 强；参数写在保险库头里，以后可以调高。
- 每条记录用 VK 加密，nonce 随机 24 字节；**附加数据（AAD）是记录的 ID 和类型**，把一条记录的密文换到另一条记录下会解密失败。
- 主密码本身不存储、不同步。忘记主密码，数据就无法恢复，界面必须说清楚。

## 文件格式

本机只有一个文件：`<配置目录>/vault.json`。

```json
{
  "format": 1,
  "vaultId": "随机 ID",
  "protected": true,
  "kdf": { "alg": "argon2id", "salt": "…", "time": 3, "memoryKiB": 65536, "threads": 4 },
  "wrappedVaultKey": "nonce+密文（base64）",
  "keyRev": "0001731000000000-0000-设备ID",
  "prunedBefore": 1723000000000,
  "records": [
    { "id": "随机 ID", "kind": "host", "rev": "0001731000000000-0003-设备ID", "data": "nonce+密文" },
    { "id": "随机 ID", "kind": "key",  "rev": "…", "data": "…" },
    { "id": "随机 ID", "kind": "host", "rev": "…", "deleted": true }
  ]
}
```

- 明文只有 `id`、`kind`、`rev`、`deleted`。这几项是合并时需要的，不含用户信息。
- `rev` 是混合逻辑时钟：16 位毫秒时间戳、4 位计数器、设备 ID，定宽，字符串比较就是先后顺序。设备 ID 存在配置目录的 `device-id`，不同步。见“同步”一节。
- `keyRev` 是主密码最后一次设置或修改的版本号，`prunedBefore` 是清理墓碑的水位，两者都参与合并。
- `protected` 为 false 表示还没有设置主密码，这时没有 `kdf` 和 `wrappedVaultKey`，`data` 是记录 JSON 的原文（只会有主机信息，不会有秘密）。
- 墓碑没有 `data`。
- `data` 解密后是这一条记录的 JSON。
- 写文件用“写临时文件再改名”，崩溃不会写坏。

### 格式演进（多平台、多版本共存）

各设备上的 Serval 版本不可能总是一致，规则如下：

- **记录里可以随时加字段。** 写入用 `vault.JSONChange`：只替换本版本认识的字段，其余字段原样保留。手机上的新版本加了字段，桌面上的旧版本编辑同一条记录也不会丢。
- **可以随时加记录类型。** 不认识的类型原样保存、原样参与合并。
- **头部字段只随 `format` 升级增加。** 旧版本遇到更高的 `format` 拒绝打开、拒绝合并，不会把新版本的头部字段写丢。
- 其他语言的客户端（Swift、Kotlin）要遵守同样的规则。加密细节：记录密文是 base64(24 字节 nonce ‖ XChaCha20-Poly1305 密文)，附加数据是 `serval-record:<kind>:<id>`；VK 的附加数据是 `serval-vault-key:<vaultId>`；Argon2id 输出 32 字节。

## 记录类型

| kind | 内容（加密） |
|---|---|
| `host` | 名称、地址、端口、用户名、分组、认证方式、引用的私钥 ID、跳板机列表、引用的代理 ID、生产环境标记、是否转发 ssh-agent、**密码**、**验证码密钥**（Base32，及可选的位数、周期、算法） |
| `proxy` | 名称、协议类型（socks5 / http）、地址、端口、用户名、**代理密码** |
| `key` | 名称、类型（ed25519 / rsa / ecdsa）、私钥（OpenSSH PEM）、公钥、指纹、**口令（可选）**、创建时间 |
| `knownhost` | 已信任的服务器：规范化的地址（如 `[example.com]:2222`）和它的公钥。记录 ID 由地址的 SHA-256 派生，两台设备各自信任同一台服务器时合并成一条 |
| `settings` | 随同步的偏好设置（外观等）。固定记录 ID `settings`，多台设备修改后按 `rev` 取较新者，写入走 `JSONChange` 保留未知字段 |
| `snippet` | 名称、正文。正文里的 `{{变量名}}`（英文字母、数字、下划线）在发送到终端时填写，填写的值不入库 |
| 以后 | 身份（用户名 + 认证方式，可被多台主机复用）、端口转发规则 |

密码直接放在 host 记录里，和主机一起加密、一起同步、一起删除，不再有“主机删了、密码留在钥匙串里”的问题。

## 同步

合并逻辑已实现（`Vault.Merge`），传输方式（同步文件夹、WebDAV 等）待实现。

- **合并规则**：两边按 `id` 对齐，同一条记录取 `rev` 较大的一方；删除是 `deleted: true` 的墓碑，同样参与比较。两台设备分别改了不同的记录，两边都保留；改了同一条，所有设备得到同一个结果。主密码的修改按 `keyRev` 取较新的一方，所以在一台设备上改了主密码，其他设备合并后也用新主密码。
- **混合逻辑时钟**：只用物理时间时，时钟快的设备永远赢。混合逻辑时钟在打开保险库和合并时，用见过的最大版本号推进本地时钟，保证“看过别人的修改之后再改”的那次一定更新，不受设备时钟偏差影响。两台设备真正同时改同一条记录时，仍按物理时间先后取舍。
- **墓碑清理**：墓碑保留 90 天，保存时清理更早的，并把 `prunedBefore` 推进到被清理墓碑的时间。合并时，本地没有、版本又早于水位的记录视为早已删除，不会被离线很久的设备带回来。代价：一台设备离线超过 90 天，它在离线前新建、又一直没同步出去的记录，回来时可能被当成已删除而丢掉。
- **主机信任记录也同步**：在一台设备上核对过指纹的服务器，其他设备不用再核对；服务器换了密钥，所有设备都会拒绝。服务器确实重装时，在主机菜单里“重置主机密钥”。
- **传输方式**：同步服务只需要“读写一个文件”。要覆盖 Windows、macOS、Linux、iOS、安卓，第一批应是 **WebDAV**（坚果云、Nextcloud、群晖都支持）和 S3 兼容存储；“同步文件夹”（iCloud Drive、Dropbox 等）只适合桌面，作为补充。
- **新设备加入**：拉取保险库 → 输入主密码 → 解开 VK。

## 平台支持

- 格式和算法都是标准的（JSON、Argon2id、XChaCha20-Poly1305），五个平台都能实现；libsodium 在 Swift 和 Kotlin 上都有成熟绑定。
- `core/vault`、`core/keys`、`core/hosts`、`core/sshconn` 是纯 Go、不依赖 MyGo、不用 cgo，可以用 gomobile 编进 iOS 和安卓客户端直接复用。
- MyGo v0.8.1 只支持 macOS、Windows、Linux 和浏览器；移动端的界面需要另做。
- “在这台设备上记住”在各平台用各自的安全存储（iOS Keychain、Android Keystore 等），不参与同步。

## 何时设置主密码、怎么解锁

- **第一次保存秘密时设置主密码**：添加私钥、在主机表单里填密码、连接时勾选“记住密码”，三者第一次发生时弹出“设置主密码”。在此之前保险库处于“未加密”状态：只有主机信息，没有任何秘密，记录以明文 JSON 保存。
- **设置主密码时换一把新的保险库密钥**并加密全部记录。旧的未加密文件即使留在备份里，也只有主机信息。
- **在这台设备上记住**（默认勾选）：把保险库密钥 VK 存进系统安全存储（`mygo.Secrets`：macOS 钥匙串、Windows 凭据管理器、Linux Secret Service），下次启动自动解锁。数据本身仍然在 `vault.json` 里；系统安全存储里只有这一把本机钥匙，不参与同步。不勾选时，每次启动先输入主密码。
- 系统没有安全存储（例如没有 Secret Service 的 Linux）时，“记住”不可用，每次输入主密码。

## 不再读取外部配置

Serval 只管理自己保险库里的主机，不读取 `~/.ssh/config`，也不提供从其他工具导入。私钥通过“密钥”页面添加（选择文件或粘贴），添加后私钥内容存进保险库，原文件删掉或移动都不影响使用，也能随同步到其他设备。`~/.ssh/known_hosts` 仍然只读地参与主机密钥校验。

当前没有需要迁移的旧数据：早期版本的 `hosts.json` 和钥匙串里的密码不再读取。

## 已确认的决定

1. 去掉两种导入：不读取 `~/.ssh/config`，不做从 MobaXterm 等工具导入。
2. 提供可选的“在这台设备上记住”。
3. 第一次保存秘密时才设置主密码。
